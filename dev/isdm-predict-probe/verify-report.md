## Per-claim findings

### Claim 1 — "predict(newdata=) on spatial fits silently drops the SPDE field even at training locations"

**CONFIRMED, and the generality claim is CONFIRMED by independent measurement (stronger
than the lane established).**

*Code.* `R/methods-gllvmTMB.R:2246-2304` is the entire `!re_zero` newdata branch. It
re-adds exactly three things: `object$use$rr_B` (L2257), `object$use$diag_B` (L2272),
`object$use$propto` (L2287). There is no `spde` branch, no `Lambda_spde`, no `g_spde`,
no `A_st`/`A_proj` anywhere in the function — `grep -n "spde" R/methods-gllvmTMB.R`
returns hits only in `print`/`tidy`/`summary` and the missing-data refit guard, none in
`predict.gllvmTMB_multi`. L2301-2303 then unconditionally emits
`"Random effects for the rr|site / diag|site / propto|species terms have been added"`,
which is the message the lane correctly calls misleading. The claim is **not** an
artifact of the probe's `spatial_latent(1 + isdm_gbif | ...)` shape: the branch is
shape-blind, and the fit carries `use$spde = TRUE, use$rr_B = FALSE`, so on a
pure-spatial fit the branch adds literally nothing.

*Independent measurement.* I refit a model sharing nothing with the probe's Part B —
plain `gaussian()`, single family, **no isdm declaration, no offset, no mixed arms**,
`spatial_latent(0 + trait | cell_id, d = 1)`, new seed — and reproduced the defect
exactly (VER[D0]-[D4]): `newdata` at the *training* rows differs from in-sample with
`sd = 0.5164` against `sd(eta) = 0.786`, `~.` is bit-identical to `~0`, and
`-diff == report$eta - fixed-only` **exactly**. So Design 126 §3.1's "affects **every**
spatial `gllvmTMB_multi` fit, not only isdm declarations" is established by measurement,
not only by code reading.

*Where the lane's evidence is weaker than what was available.* findings.md asserts "the
dropped piece **is** the field" citing `cor(−diff, u_true) = 0.82`. Correlation with the
*true* simulated field is the weaker of two available arguments and cannot establish
identity. The exact argument is structural and checkable: `fitB` has exactly one random
tier (`use$spde`), so `-diff` is the whole RE contribution identically — which my
VER[D4] confirms exactly (`all.equal` TRUE, not 0.86) on the gaussian analogue. Cite the
identity; keep 0.82 only as the corroborating "and the field is real" note.

*Scope is understated.* Of the ~30 `use` flags enumerated at `R/methods-gllvmTMB.R:3081-3090`
(`phylo_rr`, `phylo_diag`, `phylo_unique`, `kernel`, `spde`, `rr_W`, `diag_W`, `indep_*`,
`dep_*`, `*_slope`, `re_int`, …), the newdata branch handles **three**. The defect is
therefore not "spatial" — it is "every random-effect tier except `rr_B` / `diag_B` /
`propto`". Spatial is the instance that was measured; phylogenetic and kernel tiers are
unmeasured but structurally identical. Saying "spatial" understates the blast radius.

### Claim 2 — "`re_form = NA` behaves as `~.`, not `~0`"

**CONFIRMED — and the artifacts report only half of the documentation contradiction.**

*Roxygen* (`R/methods-gllvmTMB.R:2151-2158`), verbatim:

> "Random-effect formula controlling which random effects are *included* in the predicted
> linear predictor. Use the default `~ .` to include all random effects when predicting
> on training rows; pass `~ 0` (or `NA`) to predict the fixed-effects-only /
> population-mean prediction."

*Code* (`R/methods-gllvmTMB.R:2245`), verbatim:

```r
re_zero <- inherits(re_form, "formula") && identical(deparse(re_form), "~0")
```

`NA` is not a formula, so `re_zero` is `FALSE` and every RE is included. Confirmed
empirically (probe A5; my VER[C4c] shows numeric `0` fails the same way, VER[C4b] shows
`~1` does too). Only the literal string `"~0"` is honoured — `~ 0` with a space survives
because `deparse()` normalises it (VER[C4]).

🔴 **MISSED, and it is the worse half.** This guard sits *inside* the `else` (newdata)
branch. The `is.null(newdata)` branch at L2212-2229 **never reads `re_form` at all** — it
returns `object$report$eta` unconditionally. So on the package's *default* calling
convention, `predict(fit, re_form = ~0)` silently returns the **full conditional**
predictor, not the population-mean one the roxygen promises (VER[C2]: `~0 == default`
TRUE, `NA == default` TRUE). A user asking for a population-mean prediction on training
rows gets conditional predictions with no error, no warning, and no message. Design 126
§3.2 describes only the `NA`-on-newdata case; the in-sample `~0` case is a strictly
larger surface and appears in no artifact.

### Claim 3 — "`.apply_linkinv_per_row` dispatches cloglog rows to `1-exp(-exp(eta))`"

**CONFIRMED for the in-sample path. 🔴 REFUTED for the `newdata` path — an unreported
third defect that invalidates the claim as written.**

*In-sample.* `R/methods-gllvmTMB.R:326-334`: `fid ∈ {1,7,8}` dispatches on `link_id`, with
`lid == 2L → -expm1(-exp(e))` (cloglog). The in-sample branch (L2314-2326) passes the
row-aligned `family_id_vec` / `link_id_vec` under a `length(fid_vec) == nrow(out)` guard,
so each row genuinely gets its own arm. Verified by probe A2 and by the test's exact
equality assertions. **CONFIRMED.**

*newdata.* The `else` branch (L2327-2361) does something structurally different: it
collapses the per-row vectors to a **per-trait modal** family/link
(`.modal_integer_id`, L2342-2350) and then indexes it by the row's trait. On an
`isdm_sources()` fit the family varies **by source, within trait** — never by trait — so
this mapping cannot represent the model. Measured on the lane's own fixture (VER[C0]-[C1d]):
each trait carries 30 Poisson + 30 cloglog rows; the modal reduction picks Poisson
(`which.max` takes the first on a tie); and `predict(fit, newdata = dat, type = "response")`
returns `exp(eta)` for the **detection arm**, yielding "detection probabilities" in
**[0.253, 2.318]** — values above 1, silently, with no warning. `max|diff|` against the
certified in-sample response is **1.417**.

This is not a tie artifact. In any realistic iSDM the presence-only arm has more rows than
the designed-survey arm, so the survey arm loses the mode every time; the tie in the
fixture merely makes it reproducible. The defect belongs in Design 126 §3 as item 3.3 and
in ISDM-03's "NOT established" list.

*Other edge cases checked.* **Offset**: `type = "response"` transforms `eta` *including*
the offset; the artifacts state this explicitly and correctly, and VER[C5] confirms the
documented `log_support = 0` workaround is exact. **Row order / subsetting**: VER[C6]
confirms `newdata` RE alignment survives permutation. **Untested silent fallback**: on the
in-sample path, if `length(fid_vec) != nrow(out)` the code falls through to
`object$family$linkinv` (L2324-2326) — the *first trait's* link, i.e. precisely the bug
the block's own comment says it fixes. No test exercises that branch; a missing-data or
row-dropping path that breaks the alignment would silently reintroduce issue #399.
**`sigma_eps`**: `.apply_linkinv_per_row` (L313-318) uses `sigma_eps[1L]` only — a single
shared scalar across all lognormal rows (the known #856 shape). Irrelevant to isdm; noted
so it is not later mistaken for iSDM evidence.
