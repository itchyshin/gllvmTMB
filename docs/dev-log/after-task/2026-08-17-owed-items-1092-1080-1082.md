## Mathematical contract

The `aghq_ridge` control adds a Gaussian penalty to the ordinary loading block, applied in
R around the TMB objective rather than inside the template. Writing \eqn{\ell(\theta)} for
the TMB negative log-likelihood and \eqn{\lambda} for the concatenated **penalised
blocks** — `theta_rr_B` *and* `theta_rr_spde_lv`, the set `run_one()` actually reaches, and
the point on which the first version of this fix was wrong — the optimiser minimises

\deqn{F(\theta) = \ell(\theta) + \frac{1}{2\tau^2}\lVert\lambda\rVert^2,}

so its gradient is \eqn{\nabla F = \nabla\ell + \lambda/\tau^2} on the loading block and
\eqn{\nabla\ell} elsewhere. At the reported (MAP) optimum \eqn{\nabla F \approx 0}, hence

\deqn{\nabla\ell = -\lambda/\tau^2 \neq 0.}

`tmb_obj$gr()` returns \eqn{\nabla\ell}. Every diagnostic that read it therefore measured
stationarity of a function the fit was not minimising, and the error is not small: it is
exactly the omitted penalty term.

**What this change is NOT.** It does not move the penalty into the TMB objective, so
`obj$fn()` remains the *unpenalised* likelihood — deliberately, because
`.gllvmTMB_objective_components()` and `.aghq_check_penalised()` depend on that to report
`logLik()` as the likelihood at the MAP point and to warn that `AIC`/`BIC` do not apply.
It does not change any estimate, any optimisation path, or any convergence *tolerance*; it
changes only which function the reported gradient describes. It is not a fix for the
gradient's use inside the VA/EVA/MSPL routes, which carry their own penalties, and it does
not retro-correct any stored campaign result.

## Adversarial review found a real defect — and it was in my own fix

The Phase-4 fresh-context refute pass **REFUTED** the first version of the #1092 fix. This
section exists because the finding is more instructive than the fix.

`run_one()` applies the ridge to **`c("theta_rr_B", "theta_rr_spde_lv")`** — two blocks. The
accessor repaired one. So on a `latent()` + `spatial_latent()` fit the accessor returned the
raw gradient unchanged, a silent no-op on a shape it claimed to cover, while the new
`gradient_is_penalised` field asserted `TRUE` about a number that was not fully penalised —
**worse than the original defect, which at least made no claim.**

Reproduced independently before fixing (n = 50, gaussian, `aghq_ridge = 2`):
`max|theta_rr_spde_lv|` 4.249070; B-only correction **1.062241** = 4.249070/2²; B+spde
correction 0.000128, against a `gtol` of 1e-2. The same signature as the original bug — the
reported number *is* the missing penalty term.

**The lesson is recursive.** `LESSONS.md:2337` says: when you fix a wrong instrument at one
call site, grep for every other reader in the same commit. I did that faithfully — and still
shipped a broken fix, because I audited the *readers* exhaustively and took the *penalty's
definition* from the one call site I had read first. The rule needs its other half:

> **When you fix an instrument, verify what the instrument is supposed to measure — not only
> where it is read.** An exhaustive audit of readers is worthless if the quantity being
> reconstructed is itself incomplete.

The corrected fix makes that structural rather than vigilant: `.gllvmTMB_ridge_block_names`
is one constant used by the applier, the gradient instrument, and the logLik/AIC disclosure,
so the three cannot drift apart again. The disclosure was *also* wrong on the same fits
(understating the penalty) — a pre-existing instance nobody had noticed.

**My first test could not have caught it.** It passed 11/11 against a no-op fix, because
every fixture had one penalised block. The replacement fails against the one-block version
(`max_gradient` 1.1 where 0.0 is expected) — verified by reverting the accessor and
re-running, not asserted — and carries a fixture guard, because the spde block collapses at
other n/mesh settings and a collapsed block would make the test silently stop discriminating.
A first attempt at that fixture did exactly that: it passed identically under both versions.
