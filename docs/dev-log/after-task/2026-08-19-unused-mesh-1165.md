# After Task: unused `mesh=` no longer silently ignored (#1165)

**Branch**: `cursor/fix-unused-mesh-1165-b646`
**Date**: `2026-08-19`
**Roles (engaged)**: Curie, Boole, Rose, Pat, Ada

## 1. Goal

Close [#1165](https://github.com/itchyshin/gllvmTMB/issues/1165): a user can
pass `mesh =` (including a raw fmesher/INLA mesh), forget every `spatial_*()`
term, get a clean converged non-spatial fit, and write science about a spatial
mechanism that never ran. Same silent-fallback class as #1163.

## 2. Implemented

`gllvmTMB_multi_fit()` now treats a non-`NULL` `mesh` with no spatial term as
a signal, not a no-op. Mesh validation used to run only under
`use_spde` / `use_spde_slope` / `use_spde_latent_slope` -- that hypothesis
from the issue is confirmed. The unused path now:

1. warns with class `gllvmTMB_unused_mesh`, naming both possible mistakes
   (missing `spatial_*()` term, or leftover `mesh` from a term that was
   removed);
2. still calls `.gllvm_normalize_mesh()`, so a raw fmesher/INLA mesh is
   rejected with the existing `Pass mesh as a result of make_mesh()` error.

A valid `make_mesh()` object still fits as a non-spatial model after the
warning. Fits with a spatial term, and fits with `mesh = NULL`, are unchanged.

## 3a. Decisions and Rejected Alternatives

**Decision:** warn, then still validate, rather than warn-only or error-only.
**Rationale:** Shinichi's suggested warning names both user mistakes; the
issue also asked to surface the raw-fmesher vs `make_mesh()` distinction on
the path where it was missing. The issue reproduction is a raw `fm_mesh_2d`
with no spatial term -- that now warns *and* errors.
**Rejected:** error on every unused mesh, including a valid `gllvmTMBmesh`.
A leftover `make_mesh()` after dropping a spatial term is a cheap warning,
not a hard abort.
**Rejected:** validate unused mesh without warning. A valid unused mesh
would still look like a clean success.
**Confidence:** high -- the gate is the existing `use_spde*` conjunction.

## 5. Tests of the Tests

1. **Failure-before-fix.** The issue reproduction (raw `fm_mesh_2d`, no
   spatial term) and the invalid-mesh path (`mesh = "not-a-mesh"`) are
   pinned to warn then error. Before the fix those calls fitted silently;
   after it they cannot.
2. **Boundary.** A valid unused `make_mesh()` still fits, and its objective
   matches the no-mesh fit -- the warning is the signal, not a model change.
3. **Acceptance.** `mesh = NULL` with no spatial term does not fire the
   classed warning. A `spatial_indep()` fit still consumes `mesh=` without
   that warning (guard is not over-broad).
