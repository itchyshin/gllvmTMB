## 1. Goal

Fix three bot-test findings on the `engine = "julia"` route, R side only
(no GLLVModels.jl change): #1329 (post-fit methods fail on Julia fits),
#1332 (the gate rejects the exported `ordinal_logit()`), and #1334 (Julia
Gamma silently fits one shared shape where `engine = "tmb"` fits one per
trait).

## 2. Implemented

Root causes and fixes:

- **#1329.** A Julia fit has class `c("gllvmTMB_julia", "list")`. There was no
  `tidy()` method for that class. `residuals.gllvmTMB_julia()` only matched
  `"response"`/`"pearson"`. `check_gllvmTMB()` tests
  `inherits(object, "gllvmTMB_multi")` and so told the user the fit was not
  from `gllvmTMB()`.
  - New `tidy.gllvmTMB_julia()`. `"fixed"` gives the per-trait intercepts
    (named like the TMB engine's `0 + trait` columns, e.g. `traitFL`) and the
    covariate coefficients. `"ran_pars"` gives `sd_global[trait]` and the
    dispersion. `"cutpoint"` gives the ordinal cutpoints. `std.error` is `NA`
    with `inference_status = "point_estimate_only_julia_bridge"`, and
    `conf.int = TRUE` is refused with a pointer to
    `confint(fit, method = "wald")`.
    The dispatcher now stores `fit$trait_col` so the term names match.
  - `residuals(type = "simulation_rank")` builds randomized rank-PIT
    residuals from `simulate.gllvmTMB_julia()`. This is the same construction
    as the TMB engine, and binomial rows rank success counts. It returns a long
    data frame, honours masks, `seed`, `scale` and `trait`, and restores the
    caller's RNG stream. Ordinal rows are refused by the existing simulate
    gate.
  - `check_gllvmTMB()` on a Julia fit now refuses with an explanation: it
    needs the TMB gradient, Hessian and SEs. It points to `summary()`,
    simulation-rank residuals, or `engine = "tmb"`.
- **#1332.** `.gllvm_julia_family_scalar()` matched on `family$family`.
  `ordinal_logit()` reports `"ordinal_logit"`, but only `"ordinal"` was in
  the switch. `ordinal_logit` now maps to the bridge key `"ordinal"`, the
  cumulative-logit fitter (`LogitLink`, tau_1 = 0 per-trait cutpoints, the
  same parameterisation as the TMB family). The error message now lists
  exported constructors (`ordinal_logit()`, `ordinal_probit()`, `Beta()`,
  ...) instead of internal keys.
- **#1334.** GLLVModels.jl `bridge_fit` hard-codes one dispersion group for
  no-X Gamma, and `fit_gamma_gllvm` is shared-shape on the X_lv route. Its
  fixed-effect-X route already uses per-trait groups. R cannot request
  per-trait shape on the no-X route without a Julia change. So
  `gllvm_julia_fit()` now refuses multi-trait Gamma unless X is supplied
  (`[GJL-GATE-GAMMA-SHAPE]`, class `gllvmTMB_julia_gamma_shape_refused`),
  before any JuliaCall setup. `options(gllvmTMB.julia_gamma_shared_shape =
  TRUE)` opts in to the shared-shape model; the earlier warning still fires
  then. A single Gamma trait is unaffected.

## 3a. Decisions and Rejected Alternatives

- **Refuse instead of fitting per-trait Gamma.** One alternative was routing
  no-X Gamma through the X route with a pinned all-zero covariate column,
  which would get per-trait shape. It was rejected because it exposes a fake
  covariate in every payload, has no mask support, and could not be
  validated live here. Per-trait no-X Gamma belongs in GLLVModels.jl.
- **Refuse in `check_gllvmTMB()` instead of a reduced check.** None of its
  rows can be computed from the bridge payload.
- **No intervals in `tidy()`.** CI payload term names are engine-native and
  do not map one-to-one to the tidy terms.
