# After Task: Fix #1759 gllvm masking of getLoadings and getLV

**Branch**: `cursor/fix-1759-gllvm-masking-d58c`
**Date**: `2026-11-10`
**Roles (engaged)**: Emmy, Boole, Pat, Curie, Rose, Grace, Shannon

## 1. Goal

After `library(gllvm)`, `getLoadings(fit)` and `getLV(fit)` on a gllvmTMB fit were hitting `gllvm`'s S3 generics and failing with "no applicable method". The exported functions had to keep their arguments and return values, and `gllvm` must not become an Import.

## 2. Implemented

`getLoadings()`, `getLV()`, `getResidualCov()`, and `getResidualCor()` are still plain exported functions. `.onLoad` registers methods for the fit classes `gllvmTMB`, `gllvmTMB_multi`, `gllvmTMB_mspl`, `gllvmTMB_va`, and `gllvmTMB_julia` on `gllvm`'s generics when that namespace is already loaded, and a `gllvm` load hook registers them if `gllvm` is attached later. Each method forwards `object` to the existing function as `fit`. A fit produced by `gllvm` still uses `gllvm`'s own methods.

No public API / likelihood / grammar / family change.

## 3a. Decisions and Rejected Alternatives

Decision: keep the exported functions as plain functions and register forwarders on `gllvm`'s generics. Rationale: the user asked for no signature or output change, and `gllvm::getLoadings` is `function(object, ...)`. Rejected: turning `getLoadings` into a gllvmTMB generic (that changes `formals` behaviour under `UseMethod` and still cannot accept a named `fit =` once `gllvm`'s generic is the one on the search path). Rejected: adding `gllvm` to `Imports`. Confidence: high. The tests compare the search-path call with `gllvmTMB::getLoadings(fit)` on a real fit.

## 5. Tests of the Tests

The first draft called `getLoadings(fit)` inside `test_that`. Under `devtools::test()`, testthat sources the file with the package namespace as a parent, so that name is the namespace function even after `library(gllvm)`. Those `expect_identical` checks passed while `environment(getLoadings)` was still `gllvmTMB`: a false pass. The test now looks the function up from `.GlobalEnv`, asserts `find("getLoadings")` is `package:gllvm`, and calls both that function and `gllvm::getLoadings(fit)`. Without the registered method, `gllvm::getLoadings(fit)` is the "no applicable method" error in #1759.
